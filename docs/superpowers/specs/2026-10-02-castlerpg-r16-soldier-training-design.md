# CastleRPG 개정 16: 병사 훈련 (자동 생산 → 직접 훈련)

작성일: 2026-10-02
기반: 개정 2~15. 충돌 시 이 문서가 우선한다. 사용자 지시에 따라 묻지 않고 진행한다.
계기: 사용자. "막사에서 자동으로 생성되는 게 아니야."
- 개정 13 §4(자동 생산)를 SLG식 **직접 훈련**으로 바꾼다.
- 시간 규칙(1티어 1마리 3시간, 막사 레벨마다 5% 단축)은 그대로다.

## 1. 규칙 (SLG 공통 구조)

- 병사 건물(보병 막사·궁병 훈련소·기병 마구간)마다 **훈련 대기열 1개**를 둔다. 한 번에 한 묶음만 훈련한다.
- 훈련 시작: 병사 건물 창에서 수량 n을 고른다(1 ~ 묶음 상한) → [훈련].
  - 비용(자원)을 바로 차감하고, 끝나는 시각 = 지금 + n × 1마리 시간이다.
  - 1마리 시간 = `soldier_prod_sec`(10800) × `soldier_prod_level_factor`(0.95)^(L−1)
  - 묶음 상한 = `train_batch_base`(10) + `train_batch_per_level`(2) × (L − 1)
- 1티어 1마리 비용(설정, DB에서 조정 가능):

| 병종 | 식량 | 목재 | 석재 |
|---|---|---|---|
| 보병 | 30 | 20 | 0 |
| 궁병 | 25 | 30 | 0 |
| 기병 | 40 | 0 | 20 |

  설정 키: `train_cost_infantry` = `food:30|wood:20`, `train_cost_archer` = `food:25|wood:30`, `train_cost_cavalry` = `food:40|stone:20`
  - 사용자가 비용을 말하지 않아서, SLG 관례에 따라 낮게 정했다. 0으로 바꾸면 무료다.
- 완료: 끝나는 시각이 지나면 그 건물 위에 **병사 아이콘 말풍선**(자원 말풍선과 같은 방식)이 뜬다.
  - 건물을 탭하거나 건물 창의 [수령]을 누르면 n마리가 보유에 더해지고 대기열이 빈다. 알림 "보병 +n"을 띄운다.
  - 수령 전에는 새 훈련을 시작할 수 없다(409 `ready_to_collect`).
- 취소: 훈련 중 [취소] → 비용의 50%를 돌려받고 대기열을 비운다(SLG 관례).
- 건물 레벨업 중에도 훈련은 계속된다(일꾼과 별개). 레벨이 올라도 진행 중인 묶음의 끝나는 시각은 바뀌지 않는다.
- **자동 생산은 없앤다**: 개정 13의 게으른 생산 코드, `soldier_production`, 생산 알림, 테스트를 지운다(시간 공식 함수는 훈련에 재사용).

## 2. 서버

- 마이그레이션(다음 번호): `player_buildings`에 `train_count integer not null default 0`, `train_finish timestamptz null`을 더한다(병사 건물만 쓴다). 자동 생산 시계는 쓰지 않는다.
- `POST /v1/soldiers/train {building, count}`:
  - 400: 병사 건물 아님, count 범위 밖
  - 409: 진행 중(`training`), 수령 대기(`ready_to_collect`), 자원 부족(`not_enough`)
  - 원자적으로 처리하고 로그 `train_start`를 남긴다.
- `POST /v1/soldiers/collect {building}`: 끝났으면 보유 += count, 대기열을 비우고 로그 `train_collect`. 아직이면 409 `not_ready`, 비었으면 409 `empty`.
- `POST /v1/soldiers/cancel {building}`: 진행 중이면 비용의 50%(내림)를 환불하고 비운다. 로그 `train_cancel`.
- 플레이어 응답 `player.training: {barracks: {count, finish}|null, archery: …, stable: …}`
- 테스트:
  - 비용·시간·묶음 상한, 409 3종
  - 수령 전·후, 취소 환불
  - 원자성(동시 시작 2건)
  - 자동 생산이 더는 없음(시간이 흘러도 보유 불변)
  - 마이그레이션

## 3. 앱

- 상태 API(Economy, S2가 쓰던 자리를 바꾼다): `training(building_id) -> {count, finish, ready}`, `train_cost(type, n)`, `train_time(building_id, n)`, `train_max(building_id)`, `train_block(building_id, n) -> 이유`, `start_training(building_id, n)`, `collect_training(building_id)`, `cancel_training(building_id)`, 시그널 `training_changed`
  - 오프라인 save 다음 버전: 자동 생산 시계를 버리고 대기열은 비운다.
  - 온라인은 서버 응답을 쓴다. 시작·취소는 **재전송 금지**, 수령은 멱등이라 재시도해도 된다.
- **병사 건물 창(S2 영역)**:
  - 비었을 때: 병종 피규어, "1마리 2:51:00", 수량 칸(−·입력·+·슬라이더·[최대], 거래 창 수량 칸 재사용), 총비용(아이콘·부족 빨강), 총시간, [훈련]
  - 훈련 중: 진행 막대, "보병 ×8 · 남은 12:34:56", [취소(50% 환불)]
  - 완료: "보병 ×8 훈련 완료", [수령]
  - 합성 칸은 그대로 둔다.
- **월드**: 훈련 중이면 건물 머리 위에 진행 막대와 남은 시간(건설 막대 방식, 겹치지 않게 태그 배치에 합류)을 띄운다. 완료면 병사 말풍선을 띄우고, 탭하면 수령한다(수집 규칙처럼 수령할 게 있으면 탭 = 수령, 없으면 건물 창).
- **[병사] 탭 아래 3줄**: "보병 막사 · 훈련 ×8 남은 12:34:56" / "· 훈련 완료 — 수령" / "· 대기 중"
- 테스트:
  - 로직: 공식, 이유, save 이전, 자동 생산 없음
  - 입력 체크: 건물 창 수량 → [훈련](자원↓, 진행 표시), 시간 당기기(테스트 훅) → 말풍선 → 탭 수령(보유↑), [취소] 환불
  - 통합: 서버 훈련·수령·취소, 재접속 복원
