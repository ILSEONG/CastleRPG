# CastleRPG 개정 20: 성장(공용 업그레이드)

작성일: 2026-10-02
기반: 개정 2~19. 충돌 시 이 문서가 우선한다. 사용자 지시에 따라 묻지 않고 진행한다.

계기(사용자):
- 공용 업그레이드 기능을 둔다. 하단 메뉴 맨 왼쪽에 [성장] 버튼을 둔다.
- 업그레이드 항목은 공격력, 체력, 공격속도, 이동속도, 치명타 확률, 치명타 배율이다.
- 비용은 골드다. 공격력·체력은 상대적으로 싸고, 공격속도·이동속도·치명타(확률·배율)는 상대적으로 비싸다.
- 바로바로 오르는 업그레이드라서 골드 대비 효율이 높으면 안 된다.

## 1. 하단 탭

- 순서: **[성장] [영웅] [병사] [던전] [모집]**(5개, 같은 폭)
- 성장 아이콘: 각진 위쪽 화살표 + 근육(또는 위로 오르는 막대 3개)

## 2. 항목 (기획 표 `data/upgrades.csv` = DB `upgrade_defs`)

```csv
id,name,per_level,unit,max_level,cost_base,cost_growth
atk,공격력,0.5,pct,200,1000,1.05
hp,체력,0.5,pct,200,1000,1.05
aspd,공격속도,0.25,pct,100,5000,1.07
mspd,이동속도,0.25,pct,80,4000,1.07
crit_rate,치명타 확률,0.1,pp,100,6000,1.07
crit_dmg,치명타 배율,0.5,pp,100,6000,1.07
```

- L → L+1 비용 = round(cost_base × cost_growth^L), L = 현재 레벨(0부터)
  - 예: 공격력 1레벨 1,000 / 50레벨 약 11,500 / 199레벨 약 1,640만
  - 예: 공격속도 1레벨 5,000 / 50레벨 약 14.7만 / 99레벨 약 404만
- 효과(모든 아군: **영웅과 병사**):
  - 공격 × (1 + atk%)
  - HP × (1 + hp%)
  - 공격 간격 ÷ (1 + aspd%)
  - 이동 속도 × (1 + mspd%)
  - 치명타 확률 +crit_rate%p
  - 치명타 배율 +crit_dmg%p
- 최대치: 공격·체력 +100%, 공격속도 +25%, 이동속도 +20%, 치명타 확률 +10%p, 치명타 배율 +50%p

### 효율 근거 (골드 대비 낮게)

- 영웅 레벨업(SSR 1→2): 120골드로 그 영웅 HP·공격 +6%다.
- 성장 공격 1레벨: 1,000골드로 전체 +0.5%다. 출전 영웅이 4~12명이어도 영웅 레벨업보다 골드당 효과가 훨씬 낮다.
  - 이것은 영웅 레벨업 상한에 다다른 뒤 골드를 쓰는 곳이다.
- 공격속도·치명타는 레벨당 효과도 작고(0.25%·0.1%p) 시작 비용이 5~6배이며, 성장률도 1.07로 가파르다.

## 3. 치명타 규칙(전투)

- 모든 아군 공격에 **기본 치명타**를 적용한다: 확률 = crit_rate(성장, 기본 0), 배율 = 150% + crit_dmg.
- 치명타 스킬(crit)이 있는 영웅:
  - 확률 = 스킬 확률 + 성장 확률
  - 배율 = 스킬 배율 + 성장 배율 보너스
  - 굴림은 한 번만 한다.
- 피해 숫자는 기존 치명타 표시(주황 + !)를 쓴다.

## 4. 서버

- 마이그레이션 **014**(011 개정 17, 012 개정 18, 013 개정 19):
  - `upgrade_defs` 표
  - `player_upgrades(player_id, id, level, pk)`
- seed: upgrades.csv에서 넣는다. 검증: 숫자 양수, growth ≥ 1, max_level ≥ 1, 알려진 unit(pct/pp)만.
- `POST /v1/upgrade {id, count}`:
  - count 1..100. 모르는 id는 404, 최대 레벨은 409 `max_level`, 골드 부족은 409 `not_enough_gold`
  - 원자적이다(version 가드). count번 비용 합계를 한 번에 차감한다.
  - 로그 `upgrade`
- 플레이어 응답 `player.upgrades: {atk: L, …}`, gamedata `upgrades` 행
- 테스트: 비용 공식, count 합계, 상한·부족 409, 원자성, 마이그레이션

## 5. 앱

- GameData: `upgrades()`, `upgrade_cost(id, level)`, `upgrade_bonus(levels) -> {atk_pct, hp_pct, aspd_pct, mspd_pct, crit_rate, crit_dmg}`. 순수 함수.
- Economy:
  - 상태 `upgrades`
  - `upgrade(id, count)`: 온라인은 재전송하지 않는다. 오프라인은 즉시 처리하고 save 다음 버전에 저장한다.
  - 시그널 `upgrades_changed`
- 전투 반영: 영웅·병사 최종 능력치와 공격 간격·이동 속도·치명타. hero.gd·soldier.gd·skills의 공용 지점에 넣는다.
  - 반영 시점: 즉시(방치 모드든 스테이지 중이든 다음 공격부터). 능력치를 다시 읽는 지점을 하나로 둔다.
- **성장 시트**:
  - 항목 6줄, 각 줄:
    - 아이콘(로우폴리: 검·하트·쌍화살표 시계·장화·과녁·폭발 별)
    - 이름, "Lv 23 / 200"
    - 현재 → 다음 효과("+11.5% → +12.0%")
    - [강화 1,250](비용, 부족하면 비활성)
    - 길게 누르면 연속 강화(0.4초 후 가속)
    - [×10](10회 합계 비용 표시, 감당 가능한 만큼)
  - 위에 보유 골드 요약 한 줄. 아래에 "성장은 모든 영웅·병사에게 적용됩니다" 안내.
- 테스트:
  - 로직: 비용·효과 공식, 치명타 결합
  - AI 체크: 성장 공격·공격속도·치명타가 전투에 반영된다(확률 100% 상황 주입)
  - 입력 체크: 성장 탭 → [강화]로 골드가 줄고 Lv이 오른다, [×10], 길게 누르기
  - 통합: 서버 업그레이드·재접속 복원
