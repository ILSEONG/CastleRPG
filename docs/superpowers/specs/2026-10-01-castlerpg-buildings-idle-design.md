작성일: 2026-10-01
기반: 개정 2~11. 충돌 시 이 문서가 우선한다. 사용자 지시에 따라 묻지 않고 진행하며, 결정은 이 문서에 적는다.

## 2. 건물 레벨업 (SLG 분석 반영)

### 2.1 참고한 공통 구조

라이즈 오브 킹덤즈, 클래시 오브 클랜, 로드 모바일 같은 SLG의 공통 구조는 다음과 같다.

| 공통 구조 | 이 게임에 넣는 방식 |
|---|---|
| ① 본성(시청·성채)이 다른 건물의 상한 | 성채가 상한(사용자 지시) |
| ② 본성 레벨업은 성벽·핵심 건물 일정 레벨이 선행 | 성채는 성문·막사가 선행 |
| ③ 일부 건물끼리 선행 사슬(예: 병원 ← 막사) | 아래 선행 표 |
| ④ 비용은 레벨마다 기하급수로 오르는 여러 자원 | 목재·석재·식량 × 1.35^(L−1) |
| ⑤ 건설 시간도 기하급수(초반 수십 초 → 후반 수 시간) | 기본 시간 × 1.5^(L−1) |
| ⑥ 건설 대기열(일꾼) 1개 | 일꾼 1명. 동시에 한 건물만 짓는다 |
| ⑦ 완료는 서버 시각 기준. 앱을 꺼도 진행된다 | 서버 시각 기준, 꺼져 있어도 진행 |
| ⑧ 레벨마다 눈에 보이는 효과 | 아래 효과 표 |

즉시 완료(가속)·취소는 범위 밖이다.

### 2.2 건물 표 (`data/buildings.csv` = DB `building_defs`)

열: `id, name, max_level, wood, stone, food, base_sec, req1, req2`
- `wood`, `stone`, `food`: 1→2 비용. L→L+1 비용은 round(값 × 1.35^(L−1))다.
- `base_sec`: 1→2 시간(초). L→L+1 시간은 round(base_sec × 1.5^(L−1))다.
- `req1`, `req2`: 선행 건물 id다. 목표 레벨 T로 올리려면 그 건물 레벨이 T−1 이상이어야 한다.

```csv
id,name,max_level,wood,stone,food,base_sec,req1,req2
keep,성채,30,300,300,200,60,gate,barracks
gate,성문,30,150,250,0,45,quarry,
barracks,막사,30,200,120,100,40,farm,
tavern,주점,30,180,100,150,40,barracks,
lab,연구소,30,150,200,80,40,houses,
houses,민가,30,160,80,120,30,,
lumber,벌목장,30,60,80,40,20,,
quarry,채석장,30,100,40,40,20,,
farm,농장,30,80,60,20,20,,
```

- 성채를 뺀 모든 건물: 목표 레벨 T ≤ 현재 성채 레벨(사용자 지시).
- 성문은 네 성문이 레벨 하나를 같이 쓴다(지금 `gate_level`).
- 예:
  - 레벨 1→2 벌목장: 목재 60, 석재 80, 식량 40, 20초
  - 레벨 10→11 성채: 목재 약 4,470, 석재 약 4,470, 식량 약 2,980, 약 38분
  - 레벨 20→21 건물: 기본 시간 × 약 2,217배(벌목장 기준 약 12시간)

### 2.3 효과 (설정 = DB `game_config`, `data/config.csv`)

| 건물 | 효과 | 설정 키 |
|---|---|---|
| 성채 | 다른 건물 상한 | |
| 성채 | 영웅 슬롯: 성채 1~4 → 4, 5~9 → 8, 10+ → 12 | `keep_slot_tiers` = `1:4\|5:8\|10:12` |
| 성채 | 성 내부 넓이: 1~4 → 20타일, 5~9 → 24, 10+ → 28 | `keep_interior_tiers` = `1:20\|5:24\|10:28` |
| 성채 | 성 HP = 1000 + 200 × (L−1) | `castle_hp`, `castle_hp_per_level` |
| 성문 | 성문 HP = 400 × L(지금과 같다) | `gate_hp_per_level` |
| 벌목장·채석장·농장 | 분당 생산 × L(지금과 같다) | |
| 민가 | 축적 상한(분) = 720 + 60 × (L−1) | `accum_cap_min`, `accum_cap_per_house` |
| 막사 | 영웅 HP + 3% × (L−1) | `barracks_hp_per_level` = 0.03 |
| 연구소 | 영웅 공격 + 3% × (L−1) | `lab_atk_per_level` = 0.03 |
| 주점 | 모집 확률: SSR + 0.1%p × (L−1), SR + 0.3%p × (L−1)(R은 나머지) | `tavern_ssr_per_level` = 0.001, `tavern_sr_per_level` = 0.003 |

- 기존 `hero_slots` 목록과 `Balance.INTERIOR_TILES`는 단계 표로 바꾼다. 같은 값이 두 곳에 있지 않게 한다.
- 성채가 단계를 넘으면 성 내부 넓이와 영웅 슬롯이 바뀐다. 그때는 다음과 같이 처리한다.
  - 알림 "성이 넓어졌습니다!"를 띄운다.
  - 다음 방치 상태(또는 지금이 방치면 즉시)에서 월드를 다시 만든다(씬 다시 읽기).
  - 상태는 저장(오프라인)이나 서버(온라인)에 이미 있으므로 그대로 이어진다.
- 서버는 배치 길이를 새 슬롯 수에 맞춰 null로 채운다.
- 영웅 최종 HP = 기본 × 레벨 배율 × 별 배율 × (1 + 막사 보너스)
- 영웅 최종 공격 = 기본 × 레벨 배율 × 별 배율 × (1 + 연구소 보너스)
- 전투력도 이 값으로 계산한다.

### 2.4 서버

- 마이그레이션 007:
  - `building_defs` 표(2.2 열)를 만든다.
  - `player_buildings`에 모든 건물 행을 둔다(keep, gate 포함). 기존 플레이어는 keep = player_state.keep_level, gate = gate_level로 채운다.
  - 기존 자원 건물 행은 그대로 둔다. last_collect는 자원 건물만 쓴다.
  - `player_state.build_id text null, build_finish timestamptz null`: 일꾼 1명
  - `player_state.keep_level`과 `gate_level`은 지우지 않고, 완료 처리 때 함께 갱신한다(하위 호환).
- 완료 처리(게으른 완료): 플레이어 상태를 읽거나 쓰는 모든 요청 앞에서, build_finish ≤ 지금이면 그 건물 레벨 +1, 큐를 비움, economy_log `build_done`을 한 문장(버전 가드)으로 처리한다.
  - 자원 건물이 레벨업으로 완료될 때는, 지금까지 쌓인 양을 이전 레벨로 먼저 확정한다: last_collect를 그대로 두고 pending은 새 레벨로 계산한다.
  - 단순화: 레벨이 오르면 그 순간부터의 축적만 새 율이어야 정확하다. 이번에는 레벨업 시작 시 자동 수집(남은 초 유지 규칙)을 해서 경계를 깨끗하게 한다.
- `POST /v1/building/upgrade {building}`:
  - 검사 순서: 존재, 최대 레벨, 성채 상한(성채 제외), 선행(req1·req2 ≥ T−1), 일꾼 비어 있음(409 `builder_busy`), 자원(409 `not_enough`)
  - 성공하면 자원을 차감하고 build_id·build_finish를 설정한다(서버 시각 + 시간).
  - 자원 건물이면 먼저 자동 수집한다.
  - 원자적이어야 한다.
  - 응답: 플레이어 응답 + `build: {id, finish}`
- 플레이어 응답에 다음을 더한다.
  - `player.buildings`: `{id: {level, last_collect?}}`(모든 건물)
  - `player.build`: `{id, finish}` 또는 null
- `/v1/gamedata`에 `buildings` 행(2.2 열)을 더한다.
- 모집(`/v1/gacha`) 확률에 주점 보너스를 넣는다. 축적 상한에 민가를 넣는다.
- 테스트:
  - 비용·시간 공식
  - 성채 상한, 선행
  - 일꾼 중복은 409
  - 게으른 완료(시계 주입)
  - 원자성(동시 2건)
  - 007 업그레이드(기존 플레이어 레벨 채움)
  - 주점·민가 효과 반영
  - 배치 길이 확장

### 2.5 앱

- 상태: `Economy`(또는 지금 상태 경계)에 건물 레벨 전부와 일꾼 상태를 둔다.
  - 오프라인은 save v4(v3 → v4 이전은 keep/gate는 GameState 값, 나머지는 1)다.
  - 온라인은 서버 응답을 쓴다.
  - 완료 판정은 보정 시각으로 한다. 오프라인은 앱이 같은 게으른 완료를 한다.
- 효과 연결: GameState(성 HP, 성문 HP), 영웅 HP·공격(막사·연구소), 축적 상한(민가), 모집 확률(주점, 오프라인), 영웅 슬롯·성 내부(성채 단계 + 월드 다시 만들기)
- **건물 창** (ui_window):
  - 제목 "건물 이름 Lv N", 설명 한 줄
  - 효과: 현재 → 다음 레벨(예: "생산 10/분 → 20/분", "영웅 HP +6% → +9%")
  - 선행 조건 목록: ✓ 초록 / ✗ 빨강, "성채 Lv 5 필요" 같은 문장
  - 비용(목재·석재·식량 아이콘, 보유량 < 필요면 빨강), 시간 "12:34" 또는 "1시간 5분"
  - [업그레이드]: 불가하면 비활성이고 이유를 쓴다(선행 미충족 / 자원 부족 / 다른 건물 건설 중 / 최대 레벨).
  - 건설 중이면 진행 막대 + 남은 시간(매초)을 보여 준다.
- 여는 방법:
  - 건물을 길게 누른다(0.5초, 모든 건물).
  - 자원 건물을 탭했을 때 수집할 게 없으면 건물 창을 연다(있으면 지금처럼 수집).
  - 성채·막사·연구소·민가·성문(성문 탭은 영웅 명령이 우선)을 탭한다.
  - 주점·상인 탭은 지금처럼 모집·거래 창이고, 길게 누르면 건물 창이다.
- **하단 [성] 탭**: 건물 목록 시트를 연다.
  - 9개 건물 행: 아이콘 보석, 이름, Lv, 상태(건설 중 남은 시간 / ▲ 업그레이드 가능 / 잠김 이유)
  - 행을 탭하면 건물 창이 열린다.
  - 위에 일꾼 상태 한 줄 "일꾼: 막사 Lv 4 건설 중 03:21" 또는 "일꾼: 쉬는 중"
  - [성]을 다시 누르면 닫힌다(전장).
- **월드 표시**:
  - 건물 이름표를 "벌목장 Lv 3"으로 바꾼다.
  - 건설 중인 건물에는 로우폴리 비계(각진 나무 기둥 4개 + 가로대, 건물 AABB를 둘러쌈)와 머리 위 진행 막대 + 남은 시간(화면 공간, 매초)을 둔다.
  - 완료되면 비계가 사라지고, 빛 조각 연출과 알림 "벌목장 Lv 4 완료"를 보여 준다.

## 3. 방치 모드 무적

- `GameState.mode == IDLE`이면 다음과 같이 한다.
  - 성문·성(castle) 피해를 무시한다(`damage_gate`, `damage_castle`가 아무것도 하지 않음).
  - 영웅이 받는 피해도 0이다(회피·가시·흡혈 계산 전에 차단한다). 피해 숫자는 띄우지 않는다.
- 몬스터는 계속 오고, 성문 앞에서 공격 동작을 계속한다(피해 없음). 영웅은 정상적으로 때리고, 처치 골드도 그대로다.
- 살아 있는 몬스터 상한 `max_live_monsters`(120)에 닿으면 스폰을 멈춘다(지금 규칙).
- 스테이지 시작(`start_stage` → `refill`) 때 방치 몬스터는 지금처럼 정리된다.
- COUNTDOWN과 RESULT는 무적이 아니다(지금 규칙 유지). 패배는 스테이지 모드에서만 일어난다.
- HUD: 방치 모드면 상단 패널 스테이지 글자 옆에 작은 방패 아이콘과 "방치 · 무적"을 둔다.

## 4. 테스트

- **로직**:
  - 건물 비용·시간 공식
  - 성채 상한, 선행 판단(순수 함수)
  - 효과 수치(슬롯·내부 단계, 성 HP, 민가 상한, 막사·연구소, 주점 확률)
  - save v3 → v4
  - 영웅 레벨업 골드만
- **AI 체크**:
  - 방치 모드에서 성문·성·영웅 HP가 줄지 않는다(몬스터가 오래 때려도). 몬스터가 쌓인다(상한 이하).
  - 스테이지 모드에서는 피해가 들어간다.
  - 막사·연구소 레벨이 영웅 능력치에 반영된다.
- **입력 체크**:
  - [성] 탭 건물 목록, 행 → 건물 창
  - 건물 길게 누르기 → 건물 창
  - 수집할 게 없는 벌목장 탭 → 건물 창
  - [업그레이드]로 자원이 줄고 일꾼이 바쁘다(오프라인). 다른 건물 업그레이드는 비활성(일꾼)이다.
  - 시간을 당기면(테스트 훅) 완료되고 레벨이 오른다.
  - 성채 상한 비활성 이유
- **통합**:
  - 서버 업그레이드 → 일꾼 → `/v1/test/age`류 훅으로 완료 시각 당기기(훅 확장 `POST /v1/test/build_now`) → 레벨업 반영
  - 재접속 복원
  - 영웅 레벨업 골드만
- **웹 캡처(컨트롤러)**: [성] 탭 목록, 건물 창(선행 ✓/✗), 비계 + 남은 시간, 방치 무적 표시와 성문 앞에 쌓인 몬스터
